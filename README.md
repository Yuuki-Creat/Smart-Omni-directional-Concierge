# Smart-Omni-directional-Concierge

～ お客様の感動と、業務平準化のハイブリッド基盤 ～

## 1. 起動手順

1. 以下のURLをクリックしてアプリケーションを開きます。
   **[https://smart-omni-directional-concierge-frontend.onrender.com](https://smart-omni-directional-concierge-frontend.onrender.com)**

> **【補足事項】**
> バックエンド（API）の起動は、クラウドホスティングサービス「Render」の設定にて、以下のスタートコマンドを定義して稼働
> `gunicorn app:app` (WSGIサーバー `ファイル名:変数名`)

---

## 2. 使用技術

* **フロントエンド:** Vue 3
* **バックエンド:** Python, Flask
* **UI/UX要素:** PWA（デモ用）、QRコード（模擬発行）
* **データベース:** GitHub Gists（デモ用・モックデータストア）

---

## 3. AIの活用と用途

本プロジェクトの開発において、AIを活用。

* **使用用途:**
  * アイデア出し・コンセプトの練り直し（チャット形式での壁打ち）
  * ソースコードのサンプル生成
  * 開発中のエラー調査・デバッグ補助（チャット形式での壁打ち）
  * プレゼン資料の骨子作成

---

## 4. 未実装部分・注意点

### 未実装部分（今回の検証スコープ外）
* **認証・権限管理:** ユーザーのログインやロールベースのアクセス制御
* **本番DBの構築:** 今回はGistを疑似DBとして利用（将来的なRDS/Auroraへの移行を想定）
* **高度な最適化処理:** 需要予測に基づくダイナミックプライシング（動的価格）や、複雑なポイント計算ロジック

###  注意点
* ホスティングサービス（Render）の無料枠（Freeプラン）を利用してデプロイ
* 仕様上、最後のアクセスから15分以上経過するとバックエンド（サーバー）がスリープ状態に入る
* **スリープ状態からの初回アクセス時は、サーバーの再起動が行われるため、処理に1分ほど時間がかかる**（2回目以降の動作は通常通り高速になる）

---

## 5. ロジックツリー（アーキテクチャ設計）

フロントエンドとバックエンドの関心を完全に分離し、変更の影響を最小限に抑える「疎結合」な設計を採用

```text
project-root/
│
├── frontend/                         # フロントエンド (Vue 3)
│   ├── package.json                  # 依存関係定義
│   ├── vite.config.js                # Vueコードのビルド（翻訳）設定
│   ├── index.html                    # アプリケーションのエントリーポイント
│   └── src/
│       ├── App.vue                   # メインコンポーネント（顧客・店舗・工場のルートボタンとタブ切り替えを定義）
│       ├── api/
│       │   └── apiClient.js          # API通信モジュール（Pythonとの通信処理をカプセル化）
│       │
│       └── components/               # 4つのロールに応じたUIコンポーネント群
│           ├── client/               # 【サービスを利用する側】
│           │   ├── IndividualUI.vue  # ① 個人向け：事前カルテ入力、QR発行、オフピーク予約
│           │   └── CorporateUI.vue   # ② 法人向け：契約ステータス、工場預かり状況の確認
│           │
│           └── staff/                # 【サービスを提供する側】
│               ├── FactoryDash.vue   # ③ 工場向け：法人ベースロードと個人の空き枠を可視化する平準化エンジン
│               └── StoreRecp.vue     # ④ 店舗受付向け：QRコード読取、ハイタッチ接客をサポートする受付処理
│
└── backend/                          # バックエンド (Python / Flask)
    ├── requirements.txt              # 依存関係定義 (Flask, requests, flask-cors 等)
    │
    ├── app.py                        # 【ルーティング層】
    │                                 # 個人・法人・工場・店舗それぞれに向けた4つのAPIエンドポイント（URL）を提供
    │
    ├── service.py                    # 【サービス層】
    │                                 # B2C向けデータ処理、B2Bステータス取得、工場の稼働枠計算などのビジネスロジック
    │
    └── repository.py                 # 【リポジトリ層】
                                      # GitHub Gist（疑似DB）とのデータ保存・取得処理のみを担当
                                      # （将来AWS等へ移行する際はこのファイルのみを修正すれば済む疎結合設計）
```
